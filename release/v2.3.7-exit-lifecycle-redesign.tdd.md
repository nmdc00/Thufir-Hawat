# v2.3.7 Exit Lifecycle Redesign TDD

## Problem

The current exit stack has too many overlapping authorities over the same open position:

- hard invalidation
- TTL expiry handling
- exit-contract hard rules
- LLM exit consultant
- generic heartbeat triggers
- emergency liquidation protection

Each layer is individually defensible, but together they create an exit committee. That structure optimizes for control, not for letting a valid thesis compound. It also weakens attribution because a close can happen for several unrelated reasons.

The redesign must make the thesis the primary owner of the position again.

## Target Design

Every open position must follow one unified lifecycle with only three autonomous exit authorities:

1. `thesis_invalidation`
2. `emergency_risk`
3. `dynamic_profit_protection`

Supporting behavior remains, but loses independent exit authority:

- `TTL` becomes a mandatory review trigger only
- `LLM exit review` becomes advisory/modifier logic only
- generic heartbeat triggers become signals/diagnostics only

## Required Runtime Changes

### 1. Heartbeat authority reduction

`PositionHeartbeatService` must:

- keep immediate close on hard invalidation
- keep immediate close on emergency liquidation/risk collapse
- stop using generic heartbeat triggers as standalone close/reduce reasons
- evaluate a new deterministic dynamic-profit-protection path instead
- continue executing reduce-only actions once an allowed authority decides them

### 2. TTL behavior change

TTL expiry must:

- never directly close because time elapsed
- always trigger review when possible
- extend when the thesis still holds
- allow unlimited repeated extensions

The prior bounded TTL cap behavior must be removed.

### 3. LLM review authority narrowing

The LLM consultant must no longer be allowed to originate a discretionary `close` decision.

Allowed review outputs:

- `hold`
- `extend_ttl`
- `update_invalidation`
- `reduce`

Full close remains reserved for:

- invalidation
- emergency risk
- dynamic profit protection terminal state

### 4. Dynamic profit protection

Add a deterministic profit-protection evaluator that:

- activates only at large extension
- requires both extension and deterioration
- prefers `tighten invalidation` before `partial reduce`
- may escalate to `tighten + partial reduce`
- may rarely escalate to `full close` as terminal extension failure

Dynamic profit protection becomes the only non-invalidation, non-emergency path that can fully close a profitable trade.

### 5. Entry/exit contract cleanup

Trade-contract and tool-surface language should align with the redesign:

- explicit invalidation remains mandatory
- `time_exit` and default `take_profit` authority should no longer be represented as first-class autonomous close paths
- reduce-only exit reasons should map to the narrowed authority set

## Acceptance Tests

### Runtime lifecycle tests

1. `tests/core/position-heartbeat-exit-policy.test.ts`
- TTL expiry with no consultant extends and does not close
- TTL expiry with consultant `hold` extends and does not close
- TTL expiry with consultant `update_invalidation` updates invalidation and extends
- repeated TTL extensions are allowed without a cap-forced close
- invalidation breach still closes immediately

2. `tests/core/position-heartbeat.test.ts`
- generic heartbeat triggers no longer place orders by themselves
- emergency liquidation/risk still closes immediately
- dynamic profit protection can tighten invalidation
- dynamic profit protection can partially reduce
- dynamic profit protection can fully close only on terminal extension failure

3. `tests/core/llm_exit_consultant.test.ts`
- consultant schema rejects/omits `close` as a valid LLM action
- review outputs remain `hold|reduce|extend_ttl|update_invalidation`
- consult logging still persists decisions
- fallback and safe-default behavior still returns `hold`

4. `tests/core/trade-contract.test.ts`
- entry contract still requires explicit invalidation and TTL
- reduce-only exit FSM reflects the narrowed authority model
- legacy `time_exit` and `take_profit` assumptions are removed from enforcement defaults

### Integration seam tests

5. `tests/core/tool-executor-exit-policy.test.ts`
- new entries still persist an exit policy with machine-readable contract notes
- persisted notes still carry the invalidation and review contract used by heartbeat

6. New production-like lifecycle test
- open a position with explicit invalidation and TTL
- heartbeat review extends instead of closing on TTL
- later profit-protection review modifies the position through an allowed authority
- later invalidation breach still closes and clears policy

## Release Contract

Before promotion to `main`, the exact branch under test must prove:

1. TTL can no longer autonomously force a close
2. generic heartbeat triggers can no longer autonomously force a close or reduce
3. the LLM consultant can no longer autonomously full-close
4. invalidation and emergency risk still close correctly
5. dynamic profit protection is the only non-invalidation, non-emergency autonomous discretionary authority
6. focused lifecycle tests cover the happy path and the main regressions from the old design
