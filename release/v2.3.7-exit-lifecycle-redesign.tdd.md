# TDD: Exit Lifecycle Redesign — v2.3.7

## Scope

Implement the thesis-led exit redesign defined in `release/v2.3.7-exit-lifecycle-redesign.prd.md`.

This release must fix the concrete runtime mismatches between the PRD and current code:

1. generic heartbeat triggers still autonomously reduce or close positions,
2. some new trades still open without explicit machine-readable invalidation,
3. the LLM exit review still has a direct full-close path outside the narrowed authority model,
4. exit-policy persistence still permits a hybrid lifecycle where some positions are thesis-led and others are not.

The goal is not to invent a new management stack.
The goal is to remove non-thesis exit authority and make every new position carry the minimum contract required by the redesign.

## Current Proven Repo State

Current runtime already proves the redesign seams exist:

- `src/core/position_heartbeat.ts`
  - already distinguishes TTL review, invalidation breach, exit-contract evaluation, emergency handling, and generic trigger handling
  - therefore the redesign should remove authority from existing branches, not replace the heartbeat itself
- `src/core/autonomous.ts`
  - already writes per-position exit policy on both originator and quant/discovery open paths
  - therefore invalidation enforcement belongs in existing open-time wiring
- `src/core/llm_trade_originator.ts`
  - already requires `invalidationPrice` in the originator proposal schema
  - therefore the stricter contract already exists for one entry family
- `src/core/llm_entry_gate.ts`
  - already returns risk fields including `stopLevelPrice`
  - currently allows `null`, which is the seam that must be tightened
- `src/core/exit_contract.ts`
  - already provides machine-readable hard rules and contract serialization
  - currently only legacy invalidation is represented; dynamic profit protection is not yet implemented
- `src/memory/position_exit_policy.ts`
  - already persists `timeStopAtMs`, `invalidationPrice`, notes/contract, and optional prediction linkage
  - therefore the redesign should strengthen persistence invariants rather than add a second policy store

Current code also proves the spec violations:

- `src/core/position_heartbeat.ts`
  - still routes generic `fired` triggers into autonomous action branches
  - still permits direct autonomous reduce/close from `pnl_shift`, `volatility_spike`, and `time_ceiling`
- `src/core/autonomous.ts`
  - quant/discovery open path can still write exit policy with `invalidationPrice = null`
- `tests/core/autonomous-exit-policy.test.ts`
  - encoded `invalidationPrice = null` as expected behavior
- `tests/core/llm_entry_gate.test.ts`
  - encoded `stopLevelPrice = null` as acceptable behavior on approval paths

Therefore this release should:

- keep the heartbeat,
- strip generic trigger branches of direct exit authority,
- require explicit invalidation on every new trade,
- preserve emergency-risk exits,
- preserve TTL as review-only,
- defer full dynamic profit-protection implementation until a later bounded release, while preventing any other path from impersonating it.

## Design

### 1. Exit authorities must collapse to the PRD model

For this release, only these authorities may autonomously change or close a position:

- `invalidation`
- `emergency_risk`
- `dynamic_profit_protection` when explicitly encoded by machine-readable contract state

Because dynamic profit protection is not yet fully implemented in current runtime, the practical immediate result is:

- `invalidation` remains active,
- `emergency_risk` remains active,
- generic heartbeat triggers must become non-authoritative diagnostics/review inputs only.

### 2. TTL must remain review-only

`timeStopAtMs` may:

- trigger mandatory review,
- be extended,
- permit invalidation tightening,
- permit partial reduction if explicitly allowed by the redesign rules,

but may not directly close a position merely because time elapsed.

Current TTL behavior is already close to the PRD and should be preserved, with one important tightening:

- TTL review may not use the LLM as a free-standing discretionary full-close authority.

### 3. Every new trade must carry explicit invalidation

The redesign requires:

- explicit invalidation,
- machine-readable invalidation,
- rejection of trades that cannot define one.

This applies to:

- originator trades,
- quant/discovery trades,
- any future autonomous open path.

The current originator path already carries invalidation.
The quant/discovery path does not.
This release must make that asymmetry impossible.

### 4. Entry gate contract must tighten

`stopLevelPrice` must stop being nullable for approved autonomous entries.

Practical runtime rule:

- `approve` or `resize` from `LlmEntryGate` must include a finite `stopLevelPrice`
- `reject` may omit or null it

This means the entry gate becomes responsible for either:

- validating a supplied invalidation, or
- deriving a machine-readable stop level,

but never approving a trade without one.

### 5. Quant/discovery path must source invalidation deterministically

The quant path currently constructs execution decisions from expression plans that include free-form `invalidation` text but no machine-readable price.

This release must introduce a deterministic conversion seam for quant/discovery candidates.

Responsibilities:

- derive a numeric invalidation price before execution,
- fail closed if price-level invalidation cannot be computed,
- pass that invalidation into:
  - entry gate context
  - execution journaling
  - exit-policy persistence
  - trade contract serialization

### 6. Generic heartbeat triggers become advisory only

`evaluateHeartbeatTriggers(...)` may still run.
Its outputs may still be logged.
Its outputs may still feed:

- TTL review context,
- future dynamic profit-protection logic,
- observability,
- diagnostics,

but may not directly call reduce-only close/reduce execution paths.

### 7. LLM review full-close authority must narrow

The PRD is explicit:

- LLM review is not a primary exit authority
- dynamic profit protection is the only non-invalidation, non-emergency path that may escalate to full close

Therefore:

- generic TTL review may not allow unconstrained discretionary `close`
- generic cadence review may not allow unconstrained discretionary `close`

This release should prefer the narrowest implementation that matches the PRD with minimal churn.

## Runtime Contract

### 1. Position exit policy

Every newly opened autonomous position must persist:

- `symbol`
- `side`
- `timeStopAtMs`
- `invalidationPrice`
- serialized exit contract

Required invariant:

- `invalidationPrice` must be finite

If that invariant is not satisfied:

- the trade must not execute
- the policy must not be written

### 2. Exit contract baseline

`buildLegacyExitContract(...)` must no longer produce a valid open-position contract with no invalidation hard rule.

Required behavior:

- if `invalidationPrice` is absent, contract construction for autonomous opens must fail upstream
- a position may not rely on `reviewGuidance` alone as its lifecycle contract

### 3. Heartbeat behavior

For a position with valid policy:

- TTL expiry:
  - review only
  - no autonomous direct close from elapsed time alone
- Invalidation breach:
  - immediate authoritative close
- Emergency risk:
  - immediate authoritative close
- Generic trigger firing:
  - no autonomous reduce/close
  - log or feed review context only

### 4. Review behavior

Routine LLM review outputs may include:

- `hold`
- `extend_ttl`
- `update_invalidation`
- `reduce`

Routine LLM review outputs may not directly cause:

- discretionary full close outside invalidation/emergency/explicit dynamic-profit-protection terminal state

## Implementation Plan

### 1. Remove generic trigger exit authority from heartbeat

Update `src/core/position_heartbeat.ts`:

- keep `evaluateHeartbeatTriggers(...)`
- keep trigger journaling
- remove or bypass generic trigger execution paths
- retain emergency close path
- retain invalidation close path

### 2. Enforce invalidation on entry gate approvals

Update `src/core/llm_entry_gate.ts`:

- `approve` and `resize` must require finite `stopLevelPrice`
- a `null` stop on `approve` or `resize` becomes a failure or explicit rejection

### 3. Enforce invalidation on quant/discovery open path

Update `src/core/autonomous.ts`:

- before executing quant/discovery trades, resolve numeric invalidation
- pass invalidation into the gate candidate
- persist invalidation into the exit policy
- reject/block if invalidation cannot be resolved

### 4. Preserve and tighten originator path

Update `src/core/autonomous.ts` originator path only as needed:

- continue requiring originator invalidation
- ensure entry-gate-approved stop and originator invalidation do not diverge silently
- persist the final approved machine-readable invalidation price

### 5. Narrow LLM exit consultant close power

Update `src/core/llm_exit_consultant.ts` and heartbeat call sites:

- prevent generic review `close` from behaving as a standalone authority
- allow review to:
  - hold
  - extend TTL
  - update invalidation
  - reduce

## Acceptance Criteria

`v2.3.7` is complete only when all of the following are true:

1. every new autonomous trade requires explicit machine-readable invalidation
2. quant/discovery open path cannot persist `invalidationPrice = null`
3. generic heartbeat triggers no longer autonomously close or reduce positions
4. TTL expiry triggers review only, never direct exit
5. emergency risk remains authoritative
6. invalidation breach remains authoritative
7. routine LLM exit review cannot act as a standalone full-close authority
8. test suite encodes the thesis-led contract rather than the prior hybrid behavior

## Risks / Deferred Work

This release intentionally does not fully ship dynamic profit protection.

Deferred follow-up:

- explicit contract/state representation for dynamic-profit-protection arming
- `R`-based extension eligibility
- deterioration detection inputs
- adaptive partial-reduction sizing
- terminal-extension full-close branch with explicit reason-code family

That follow-up should be implemented as a separate release after this one removes the current spec violations.
