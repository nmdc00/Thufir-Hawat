# v2.5 Test Plan: Runtime Coherence & Risk Containment

## Purpose

This plan defines the proof required before `release/v2.5` can promote to `develop`, then to
`main`, then to production. It is organized around the release contracts in
`release/v2.5-runtime-coherence-and-risk-containment.prd-tdd.md`.

v2.5 is not complete when code compiles. It is complete when the runtime proves:

- closes are attributable,
- portfolio exposure is contained before LLM spend,
- deterministic gate skips are observable,
- originator performance is measured,
- heartbeat checks are cheap and reliable,
- operational tables have bounded lifecycle,
- `STATE.md` records the deployed truth.

## Test Levels

### 1. Branch-Level Focused Tests

Each feature branch must pass its focused test file(s) before merge to `release/v2.5`.

Expected command shape:

```bash
pnpm exec vitest --run <focused-test-files>
pnpm exec tsc --noEmit
```

If full typecheck is temporarily blocked by unrelated release-base failures, the branch owner must
record the exact blocker in the PR body and the release branch must resolve it before promotion.

### 2. Release-Branch Integration Tests

After each merge wave into `release/v2.5`:

```bash
pnpm exec tsc --noEmit
pnpm exec vitest --run
```

If the full suite is too slow for intermediate waves, run focused suites after Wave 1 and Wave 2,
but the full suite is mandatory before `release/v2.5 -> develop`.

### 3. Production-Like Contract Tests

Before promoting `develop -> main`, run release-contract validation on the exact promotion SHA.
The validation must use a production-like SQLite DB fixture or a sanitized production snapshot for
all persistence contracts.

### 4. Production Post-Deploy Checks

After deploy, run the SQL/runtime checks in this plan against the production DB/service and record
results in `STATE.md`.

## WS1: Exit Attribution

### Contract

Every new autonomous or manual reduce-only close persists a canonical close reason and authority in
fill/journal/dossier metadata. Attribution failures must fail open and alert; they must not block
the close.

### Unit Tests

- `src/core/exit_reasons.ts`
  - accepts every canonical reason,
  - accepts the reserved fallback reason,
  - rejects unknown strings,
  - normalizes existing `exit_mode` values where compatibility is required.

- `src/core/position_heartbeat.ts`
  - thesis invalidation branch emits `thesis_invalidation`,
  - TTL/time stop branch emits `thesis_time_stop`,
  - exit-contract branch emits `exit_contract_rule`,
  - exit consultant branch emits `llm_exit_consult`,
  - liquidation guard emits `liquidation_guard`,
  - emergency close emits `emergency_close`,
  - legacy trigger branches emit the correct `legacy_trigger:*` value.

- `src/core/tool-executor.ts`
  - `reduce_only=true` with valid close/exit reason persists the reason,
  - missing/invalid reason produces fallback attribution and logs an error,
  - close still executes on fallback attribution.

### Lifecycle Tests

Seed or open a paper perp position, trigger a close path, then assert:

```sql
SELECT json_extract(metadata, '$.reason') AS reason,
       json_extract(metadata, '$.authority') AS authority
FROM paper_perp_fills
WHERE reduce_only = 1
ORDER BY created_at DESC
LIMIT 1;
```

Expected: non-null canonical `reason`, non-null `authority`.

### Production Check

After deploy:

```sql
SELECT json_extract(metadata,'$.reason') AS reason,
       json_extract(metadata,'$.authority') AS authority,
       COUNT(*) AS fills
FROM paper_perp_fills
WHERE reduce_only = 1
  AND created_at > :deploy_time
GROUP BY 1, 2
ORDER BY fills DESC;
```

Pass condition: all new rows have canonical reasons. Any fallback/unattributed reason is an alert,
not an immediate release failure if the close executed safely.

## WS3: Portfolio Exposure Guard

### Contract

Autonomous open candidates are checked for gross, net, cluster, and duplicate-underlying exposure
before any LLM entry-gate consult.

### Pure Function Tests

Use table fixtures for:

- gross cap breach,
- net cap breach,
- short-heavy current-book fixture rejects new short,
- short-heavy current-book fixture allows risk-reducing long when net exposure improves,
- cluster cap breach,
- duplicate underlying same-side block (`XYZ:CL` + `XYZ:BRENTOIL` as `energy:oil`),
- duplicate underlying opposite-side allowance when net risk improves,
- unmapped symbol becomes singleton cluster,
- `enabled=false` bypasses guard.

### Integration Tests

Mock or fake:

- position book with saturated exposure,
- equity source,
- LLM entry gate.

Assert:

- blocked candidate does not invoke the LLM,
- `llm_entry_gate_log.reason_code` is one of:
  - `exposure_gross_cap`,
  - `exposure_net_cap`,
  - `exposure_cluster_cap`,
  - `exposure_duplicate_underlying`,
- `llm_consulted = 0`,
- decision payload includes computed exposure details.

### Production-Like Replay

Replay the 2026-06-12 production book fixture:

- 12 open paper positions,
- 10 short / 2 long,
- approx 4.4x gross exposure,
- approx 2.9x net short exposure,
- `XYZ:CL` and `XYZ:BRENTOIL` same-side oil duplication.

Pass conditions:

- new energy/oil short rejected,
- new crypto-major short rejected if cluster/net cap breached,
- risk-reducing long allowed when it reduces net exposure and does not create a duplicate same-side risk.

## WS4: Gate-Call Economy

### Contract

Candidates failing deterministic prechecks are rejected and journaled without an LLM call.

### Unit Tests

- Cooldown:
  - rejected `symbol+side` candidate creates cooldown state,
  - identical candidate inside `gateCooldownMinutes` is suppressed,
  - suppression journals `reason_code='cooldown_suppressed'`,
  - suppression records `llm_consulted=0`,
  - LLM mock call count remains zero.

- Cooldown bypass:
  - edge improvement `>= last_edge * 1.25` reaches LLM,
  - fresh catalyst timestamp newer than last reject reaches LLM.

- Edge floor:
  - candidate below `autonomy.minEdge` rejects before LLM,
  - reason code is `edge_too_low`,
  - `llm_consulted=0`.

- Same-side stacking:
  - same symbol and same side open position rejects before LLM,
  - reason code is `same_symbol_stacking`,
  - `llm_consulted=0`.

- Regression:
  - clean candidate invokes LLM exactly once,
  - approval/resize/reject LLM responses still persist with `llm_consulted=1`.

### Integration Metrics

Release branch must include a queryable baseline comparison:

```sql
SELECT llm_consulted, COUNT(*) AS decisions
FROM llm_entry_gate_log
WHERE created_at > :deploy_time
GROUP BY llm_consulted;
```

Seven-day production acceptance:

- consulted calls down at least 80% vs trailing pre-deploy baseline,
- approves/day within +/-20% unless fewer candidates are available,
- no increase in `book_conflict` or same-side conflict approvals,
- approval expectancy does not degrade versus trailing baseline once enough closes exist.

## WS2: Originator Scorecard

### Contract

Nightly job computes 7/30-day post-cutoff metrics for originator discipline and quality, persists
them, and renders latest values on the Learning dashboard.

### Preflight Proof

Before finalizing implementation, prove how executed trades are classified:

- originator-linked trades can be joined from proposal/gate/trade/fill records, or
- missing linkage is explicitly represented as unknown/excluded.

Required test fixture must include:

- originated trade,
- quant-path trade,
- rejected gate decision,
- null proposal scan cycle,
- pre-cutoff rows that must be excluded,
- empty post-cutoff window.

### Persistence Tests

- table/migration creates `originator_scorecard`,
- 7-day and 30-day rows are written,
- rerun for the same date/window replaces or upserts instead of duplicating,
- empty windows write null metrics instead of throwing,
- all queries enforce `learning.cleanDataCutoff`.

### Metric Tests

Assert exact expected values for:

- `scan_cycles`,
- `null_proposal_rate`,
- `originated_trades`,
- `quant_trades`,
- `originated_share`,
- `originated_win_rate`,
- `originated_expectancy_usd`,
- `quant_win_rate`,
- `quant_expectancy_usd`,
- `gate_approves`,
- `gate_consult_calls`.

### Dashboard Tests

- API returns latest row for each window,
- Learning tab renders 7/30-day values,
- target badges render pass/fail/insufficient-data states,
- missing table or empty data returns a graceful empty state.

### Production Check

After first nightly run:

```sql
SELECT *
FROM originator_scorecard
ORDER BY computed_at DESC, window_days ASC
LIMIT 2;
```

Pass condition: one latest 7-day row and one latest 30-day row exist and dashboard displays them.

## WS5: Heartbeat Repair

### Contract

Scheduled heartbeat/liveness checks do not route through the full conversation/tool loop and do not
emit repeated error logs every tick.

### Unit Tests

- `ThufirAgent.handleHeartbeat` uses info/trivial client when available,
- fallback to main LLM works when info client is absent,
- `ConversationHandler.chat` is not called,
- `notifications.heartbeat.timeoutMs` default is 30000ms,
- configured timeout overrides default,
- degraded modes are preserved:
  - `silent` returns empty string,
  - `notify` returns degraded message,
  - default returns `HEARTBEAT_OK`.

### Failure-Throttling Tests

- first failure logs warn,
- repeated failure inside one hour does not log warn again,
- escalation/notification occurs no more than once per six hours if notification path is configured.

### Production Check

Log query/pass condition:

- zero new `Heartbeat conversation error` lines over 48h,
- heartbeat job still returns an accepted liveness response.

## WS6: Data Lifecycle

### Contract

Operational tables with bounded value are pruned by policy without deleting retained trade-linked
artifacts or user chat data.

### Registry Tests

- registering the same policy twice is idempotent,
- unregistered tables are never touched,
- missing optional tables are skipped safely,
- counts returned per table/kind are accurate.

### Policy Tests

Seed `decision_artifacts` with:

- expired `position_heartbeat_journal`,
- expired `expression`,
- expired `hypothesis`,
- expired `signal_cluster`,
- retained `perp_trade_*`,
- retained `execution_learning_case`,
- retained `adaptive_*`,
- fresh rows of every kind.

Assert only expired non-retained kinds are deleted.

Seed `llm_entry_gate_log` with:

- expired rejects,
- expired approve/resize rows,
- fresh rejects.

Assert only expired rejects are deleted.

Seed `opportunity_rank_logs` if table exists:

- expired rows deleted,
- fresh rows retained.

### SQLite/Vacuum Tests

- retention job does not call full `VACUUM`,
- daily job may call `PRAGMA incremental_vacuum`,
- logs indicate when incremental vacuum cannot reclaim file size because auto-vacuum is disabled,
- one-time manual prune script is the only path that runs full `VACUUM`.

### Production Check

Before manual prune:

```sql
SELECT kind, COUNT(*) AS rows
FROM decision_artifacts
GROUP BY kind
ORDER BY rows DESC;
```

After manual prune:

- DB file size target: approximately <= 600 MB,
- weekly growth target: flat within +/-5% after retention job runs.
