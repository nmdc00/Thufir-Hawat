The close/execution learning path is producing evidence, but forecast calibration is not. The dashboard's

not have a real comparator probability.

Current resolved predictions have model probabilities, final outcomes, and PnL, but no trustworthy comparator:

```text
resolved_false / final / learning_comparable=0: 240 rows, avg_model=0.7275, avg_market=0.5, pnl=-283.2361
resolved_true  / final / learning_comparable=0:  70 rows, avg_model=0.7329, avg_market=0.5, pnl= 102.4423
```

The `0.5` baseline is intentionally treated as synthetic for perp predictions and must not be promoted to comparable
forecast data.

## Problem

Thufir currently records two different learning families:

1. **Execution learning**: whether trades made money, whether exits were good, and whether setup scopes should be
   downweighted or blocked.
2. **Comparable forecast learning**: whether Thufir's stated probability was calibrated and whether it beat a
   comparator probability.

Execution learning now has production evidence. Comparable forecast learning has none.

The missing contract is a real `prediction_market_probability` for autonomous perp opens. For perps, market price is
not a probability. A BTC mark price of `$76,000` does not imply a 76% chance of a profitable long. Therefore
`prediction_market_probability` must be a baseline probability for the same forecast target as
`prediction_model_probability`.

Without this:

- Forecast accuracy windows stay empty.
- Brier/model-vs-market deltas are unavailable.
- The system cannot distinguish overconfident but lucky trading from calibrated forecasting.
- Any arbitrary `0.5` comparator would contaminate the calibration panel and make the dashboard misleading.

## Goal

Create a production-safe perp prediction baseline system that produces a real comparator probability for each eligible
autonomous perp open.

The comparator should answer:

> Given this setup context, what is the baseline probability that the trade will close profitably before thesis
> invalidation or TTL expiry?

This enables:

- Non-empty comparable prediction windows.
- Brier score comparison between Thufir and a base-rate benchmark.
- Calibration buckets for Thufir's forecast confidence.
- Explicit contamination controls so fake or synthetic baselines never enter `learning_examples`.

## Non-goals

- Do not treat perp mark price as a probability.
- Do not mark `market_probability = 0.5` rows comparable.
- Do not use LLM confidence as both model and comparator probability.
- Do not backfill rows as comparable unless their comparator source is auditable.
- Do not change the close finalizer or trade policy materialization contracts in this feature.

## Forecast Target

For v2.4, use one canonical target:

```text
The trade closes with positive net realized PnL before its thesis TTL/invalidation.
```

Store this target explicitly in prediction metadata so future targets can coexist.

Recommended metadata:

```json
{
  "forecastTarget": "positive_net_pnl_before_ttl_or_invalidation",
  "baseline": {
    "source": "segment_history_blended",
    "probability": 0.385,
    "sampleCount": 20,
    "priorProbability": 0.42,
    "priorStrength": 20,
    "segmentKey": "signalClass=momentum_breakout|marketRegime=high_vol_expansion|triggerReason=technical|symbolClass=alt",
    "fallbackLevel": "signal_regime_trigger_symbol_class"
  }
}
```

## Baseline Model

### Primary baseline: empirical segment history with shrinkage

Compute the comparator from recent execution/close evidence:

```text
baseline_probability = (wins + prior_strength * prior_probability) / (samples + prior_strength)
```

Definitions:

- `win`: closed trade with `netRealizedPnlUsd > 0`.
- `samples`: matching historical closes for the segment.
- `prior_probability`: broader fallback win rate.
- `prior_strength`: configurable pseudo-count, default `20`.

### Segment dimensions

Use a hierarchy, from narrow to broad:

1. `signalClass + marketRegime + triggerReason + symbolClass + direction`
2. `signalClass + marketRegime + triggerReason + symbolClass`
3. `signalClass + marketRegime + triggerReason`
4. `signalClass + marketRegime`
5. `signalClass`
6. global perp execution prior

Do not include raw symbol by default. Symbol-level baselines are useful for policy gating, but they overfit forecast
calibration when samples are small.

### Eligibility

A prediction can become comparable only when:

- `prediction_model_probability` is finite and in `[0.01, 0.99]`.
- `prediction_market_probability` is finite and in `[0.01, 0.99]`.
- comparator source is not `synthetic_0_5`.
- comparator source is not `missing`.
- forecast target is present.
- baseline has either:
  - at least `minComparableSamples` real samples at any fallback level, or
  - a blended source with an auditable prior and at least one real segment/fallback sample.

Default:

```yaml
autonomy:
  perpPredictionBaselines:
    enabled: true
    priorStrength: 20
    minComparableSamples: 5
    lookbackDays: 90
    decayHalfLifeDays: null
    target: positive_net_pnl_before_ttl_or_invalidation
```

## Behavioral Finance Requirements

This feature exists to prevent confidence from masquerading as calibration.

Required behavior:

- Compare every model probability against a base rate.
- Penalize overconfidence through Brier score and calibration bins.
- Surface when model confidence rises while base-rate evidence is poor.
- Preserve "good process, bad outcome" separately from "bad process, lucky outcome".
- Keep execution-quality learning separate from forecast calibration.

Production example:

```text
momentum_breakout + high_vol_expansion:
20 execution cases
win_rate = 0.35
net_pnl = -26.1082
avg_quality = 0.527
```

If Thufir predicts `0.72` for that setup, the comparator should be near the smoothed base rate, not `0.5`.

## Implementation Plan

### New module

Create `src/core/perp_prediction_baselines.ts`.

Types:

```ts
export type PerpForecastTarget = 'positive_net_pnl_before_ttl_or_invalidation';

export type PerpPredictionBaselineInput = {
  symbol: string;
  side: 'buy' | 'sell';
  signalClass: string | null;
  marketRegime: string | null;
  triggerReason: string | null;
  symbolClass: string | null;
  session: string | null;
  volatilityBucket: string | null;
  liquidityBucket: string | null;
  forecastTarget?: PerpForecastTarget;
};

export type PerpPredictionBaseline = {
  probability: number | null;
  comparable: boolean;
  source: 'segment_history_blended' | 'global_prior' | 'missing';
  fallbackLevel: string | null;
  sampleCount: number;
  wins: number;
  priorProbability: number | null;
  priorStrength: number;
  segmentKey: string | null;
  exclusionReason: null | 'missing_comparator' | 'insufficient_samples' | 'synthetic_comparator';
};
```

Main function:

```ts
export function resolvePerpPredictionBaseline(
  config: ThufirConfig,
  input: PerpPredictionBaselineInput,
  db?: Database.Database
): PerpPredictionBaseline
```

## Acceptance Criteria

- New autonomous perp opens can create comparable predictions without caller-supplied `prediction_market_probability`.
- Comparator probability is grounded in historical execution/close evidence with shrinkage.
- `learning_examples` stays empty when no real comparator exists.
- `market_probability=0.5` synthetic perp rows never become comparable.
- Dashboard explains why prediction accuracy windows are empty.
- First production day after deployment shows:
  - comparator diagnostics populated,
  - no synthetic comparable rows,
  - comparable prediction rows only when baseline source is auditable.

## Open Questions

1. Should pure global priors ever be comparable, or should they only be stored as non-comparable diagnostics?
2. Should the target be positive net PnL, captured R above zero, or composite close quality above threshold?
3. Should live and paper evidence share priors, or should live start with paper-informed but separately tagged priors?
4. Should baseline probability use recency decay before we have enough stable samples?
5. Should the LLM see the baseline probability before proposing confidence, or should baseline remain a post-hoc calibration benchmark?
