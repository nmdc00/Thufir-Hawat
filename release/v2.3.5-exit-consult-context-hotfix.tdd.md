# v2.3.5 Exit Consultant Context Hotfix TDD

## Problem

Production still logs `LLM execution context missing; defaulting to FULL_AGENT` during startup heartbeat review of open paper positions. The exercised runtime path is `PositionHeartbeatService -> LlmExitConsultant.consult()`.

## Root Cause

`LlmExitConsultant.consult()` calls both the main and fallback LLM clients without `withExecutionContext(...)` or `withExecutionContextIfMissing(...)`. Because the live consultant runs from a background heartbeat tick, there is no ambient chat/session context, so `InfraLlmClient` emits the missing-context warning for each primary and fallback provider call.

## Minimal Fix

- Wrap the main consultant call with `withExecutionContextIfMissing({ mode: 'LIGHT_REASONING', critical: false, reason: 'exit_consultant_main', source: 'heartbeat' }, ...)`.
- Wrap the fallback consultant call with `withExecutionContextIfMissing({ mode: 'LIGHT_REASONING', critical: false, reason: 'exit_consultant_fallback', source: 'heartbeat' }, ...)`.

- fallback-path call sees `getExecutionContext()` with `reason = exit_consultant_fallback`
