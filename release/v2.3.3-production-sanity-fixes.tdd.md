# TDD: Production Sanity Fixes — v2.3.3

`v2.3.3` is the correct patch number on the current `v2.3` line.

This patch closes three live production issues:

1. `PositionHeartbeat` repeatedly hits Hyperliquid `429 Too Many Requests` while loading mids.
2. Telegram channel-monitor relevance screens call the LLM without an execution context and emit `LLM execution context missing; defaulting to FULL_AGENT`.
3. The LLM entry gate is using polluted signal-history evidence:
   - blocked attempts count toward `sampleCount`
   - recent-window noise is described as trade history
   - the prompt implicitly treats `>10%` edge as a trade-approval floor instead of only a leverage scale-up bar

## Release Contract

`v2.3.3` is done only when all of the following are true:

- Hyperliquid mids are shared, cached, and stale-if-error across client instances.
- A warm mids cache is returned on transient `429`/`5xx` refresh failures instead of throwing.
- Background Telegram monitor relevance checks run under an explicit non-chat execution context.
- The channel-monitor relevance path no longer relies on the `FULL_AGENT` fallback context.
- Entry-gate signal history excludes blocked attempts from trade sample counts and win-rate denominators.
- Entry-gate comparable evidence prefers narrower scope first:
  - `signalClass + symbolClass + marketRegime`
  - `signalClass + symbolClass`
  - `signalClass`
- When no resolved comparable evidence exists, the prompt says so explicitly instead of fabricating weak track record language from blocked attempts.
- The prompt aligns with configured mechanical thresholds and states that `>10%` edge is only a leverage scale-up bar, not a general approval threshold.

## Red Tests

### Shared mids cache / stale fallback

Add regressions in `tests/execution/hyperliquid-client-cache.test.ts` proving:

- `getAllMids()` coalesces across separate `HyperliquidClient` instances.
- a fresh cache suppresses duplicate upstream `allMids` / `metaAndAssetCtxs` fanout.
- after the mids TTL expires, a transient refresh failure with a warm cache returns stale mids instead of throwing.

### Channel monitor LLM context

Add a regression in `tests/intel/channel_monitor_briefing.test.ts` proving:

- the relevance pre-screen runs under `withExecutionContextIfMissing`
- the active context inside `infoLlm.complete()` is:
  - `mode: LIGHT_REASONING`
  - `critical: false`
  - `reason: telegram_monitor_relevance`
  - `source: gateway`

### Comparable signal performance semantics

Add regressions in `tests/core/signal-performance.test.ts` proving:

- blocked entries do not count toward `sampleCount`
- unresolved executed entries do not count toward `sampleCount`
- `symbolClass` can be derived from `symbol` when missing from journal payloads
- comparable summary falls back from:
  - `signal + symbolClass + regime`
  - to `signal + symbolClass`
  - to `signal`

### Entry-gate prompt contract

Add regressions in `tests/core/llm_entry_gate.test.ts` proving:

- a summary shaped like `32 blocked + 3 resolved` is rendered as `3 resolved trades`, not `35 trades`
- the prompt includes the configured mechanical floor
- the prompt explicitly states that `>10%` is only a leverage scale-up bar

## Implementation

- Extend `src/execution/hyperliquid/client.ts` with shared `getAllMids()` cache/inflight maps, 30s mids TTL, and stale-on-transient-error behavior.
- Update `src/gateway/index.ts` to wrap the Telegram relevance pre-screen with `withExecutionContextIfMissing`.
- Extend `src/memory/perp_trade_journal.ts` with optional `symbolClass`.
- Extend `src/core/signal_performance.ts` with comparable-scope summaries that exclude blocked/unresolved entries from realized trade stats.
- Update `src/core/llm_entry_gate.ts` to use comparable summaries and prompt wording aligned with configured thresholds.
- Update `src/core/autonomous.ts` to pass `symbolClass` into entry-gate candidates, record it in journals, and use comparable summaries for Kelly sizing inputs.
