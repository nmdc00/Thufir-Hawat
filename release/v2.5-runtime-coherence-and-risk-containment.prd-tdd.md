# PRD/TDD: Runtime Coherence & Risk Containment — v2.5

## Production Evidence

As of the production inspection on 2026-06-12 (server `77.42.29.26`, DB `~/.thufir/thufir.sqlite`):

| Surface | Count / Finding |
|---|---:|
| Open paper positions | 12 (10 short / 2 long), unrealized **+$78.40** |
| Gross open notional | ~$1,245 on ~$283 true equity (**~4.4× gross**) |
| Net directional exposure | ~$810 net short (**~2.9× equity**, one macro thesis) |
| Same-underlying duplication | `xyz:CL` + `xyz:BRENTOIL` shorts = $422 combined (1.5× equity in one commodity) |
| Entry gate LLM calls | 26,063 total: **25,649 reject / 109 approve / 305 resize (98.4% reject)** |
| Gate edge separation | avg edge approved 0.091 vs rejected 0.073 — near zero discrimination |
| Close fills with a recorded trigger reason | **0 of 251** (`json_extract(metadata,'$.reason')` is null on every reduce-only fill) |
| Heartbeat conversation failures | 3,622 timeouts since April 18 (`LLM request (openai/gpt-5.4) timed out after 10000ms`, every ~5 min) |
| `decision_artifacts` rows | 2,819,886 (2.0 GB, 78% of DB); no prune path exists; `expires_at` never enforced by deletion |
| v1.98 originator success criteria | Defined in `docs/v1.98-vision.md`; **none are computed anywhere** |

Two conclusions frame this release:

1. The book is currently green and exit management is visibly improved post-v2.3.x — but the account's
   single biggest risk is now **portfolio-level**: nothing prevents twelve positions that are one correlated
   macro bet, or the same underlying expressed twice.
2. Several behaviors that our own design documents already prohibit are still live in runtime:
   unattributed exits (v2.3.7), unbounded LLM gate spend (`LLM_INFRASTRUCTURE_AND_EXECUTION_CONTROL.md`),
   and unmeasured originator performance (v1.98 vision).

v2.5 is therefore not a new capability release. It closes the gap between what the design documents
specify and what production actually does, and adds the one risk control no document yet owns.

## Problem

Five distinct runtime failures share one root cause — the system acts but does not account for itself:

1. **Exits are unattributable.** Five reduce-only call sites in `src/core/position_heartbeat.ts`
   (lines ~319, 373, 479, 523, 566) plus the tool-executor close path place orders without recording
   *which authority* closed the position (thesis invalidation, TTL, exit consultant, liquidation guard,
   emergency, manual). The entire v2.2 adaptive-learning thesis — "learn decision lessons, not PnL" —
   is unbuildable without this attribution.
2. **The originator bet is unmeasured.** v1.98 shipped with explicit success criteria
   (null-proposal rate > 60%, originated win rate > 25%, > 50% of executed trades LLM-originated).
   The data to compute them exists in `llm_entry_gate_log`, `llm_trade_proposals`, and
   `paper_perp_fills`, but no job computes them. We cannot currently say whether LLM-primary
   trading is working or merely running.
3. **No portfolio-level exposure authority exists.** `wallet.exposure.{maxPositionPercent,maxDomainPercent}`
   and `wallet.perps.maxTotalNotionalUsd` exist in `src/core/config.ts` but are not enforced on the
   autonomous open path — the live book proves it. There is no net-directional cap and no concept of
   a correlation cluster, so `CL` and `BRENTOIL` count as two unrelated trades.
4. **Gate spend is unbounded.** The `PositionBook.hasConflict` fast-path
   (`src/core/llm_entry_gate.ts:594`) is the only deterministic pre-check. Everything else — including
   candidates re-evaluated for the same symbol every scan cycle, sub-floor edges, and same-side
   stacking — reaches the LLM. 98.4% of 26K calls were rejections.
5. **Operational data has no lifecycle.** `decision_artifacts` grows ~25–30 MB/day forever;
   the heartbeat conversation burns a failed large-model call every 5 minutes and has for two months.

## Goal

Make the runtime *coherent with its own design* and *contained at the portfolio level*:

```text
every close      -> carries its closing authority into the fill record and dossier
every scan cycle -> spends LLM calls only on candidates that pass deterministic screens
every open       -> passes portfolio-level exposure checks (gross, net, cluster, duplicate-underlying)
every week       -> originator success criteria are computed and visible
every day        -> bounded tables stay bounded; the heartbeat is cheap and reliable
```

## Non-goals

- No changes to thesis generation, originator prompts, or exit-consultant reasoning.
- No changes to sizing math (Kelly, leverage geometry) beyond *blocking* at portfolio caps.
- No new learning families — v2.2/v2.4 contracts are consumed, not modified.
- No live-mode enablement; everything here applies identically to paper and live paths.
- No retroactive backfill of exit reasons for historical fills (they remain null and are excluded
  from attribution-dependent analytics by definition).

## Product Thesis

A trading system earns the right to get smarter only if it can answer, from its own records:
*why did I exit, what am I exposed to, and is my judgment beating its baseline?*
Today Thufir can answer none of these. Every workstream in v2.5 makes one of those questions
answerable or enforces the answer.

## Scope

### WS1 — Exit Attribution (completes v2.3.7)

Every reduce-only order placed by any autonomous authority must carry a machine-readable
`closeReason` that survives into `paper_perp_fills.metadata` (and the live fill journal), the
position-heartbeat journal, and the trade dossier.

Canonical reason codes (closed enum, validated at write time):

```text
thesis_invalidation | thesis_time_stop | exit_contract_rule | llm_exit_consult
liquidation_guard   | paper_liquidation | equity_guard       | manual_command
emergency_close     | legacy_trigger:<pnl_shift|volatility_spike|time_ceiling>
```

### WS2 — Originator Scorecard (operationalizes v1.98 success criteria)

A nightly scheduler job computes, over rolling 7/30-day windows, on post-cutoff data only:

- null-proposal rate per scan cycle (target > 60%)
- share of executed trades that are LLM-originated (target > 50%)
- win rate and expectancy of originated vs quant-path trades (target: originated > 25% and > quant baseline)
- gate verdict → outcome join (approve/resize PnL vs reject counterfactual where measurable)

Results persist to a `originator_scorecard` table and surface on the dashboard Learning tab.
A `learning.cleanDataCutoff` config date excludes bug-era trades from all scorecard windows.

### WS3 — Portfolio Exposure Containment (new authority)

A deterministic `PortfolioExposureGuard` runs in the hard-risk-check layer of
`src/core/autonomous.ts` — *before* the LLM entry gate, after per-trade wallet checks:

1. **Gross cap:** total open notional ≤ `maxGrossLeverage` × equity (default 3.0).
2. **Net-directional cap:** |long notional − short notional| ≤ `maxNetLeverage` × equity (default 2.0).
3. **Cluster cap:** per-cluster notional ≤ `maxClusterPercent` of equity (default 75%).
   Clusters are static config-defined tags (`crypto-majors`, `crypto-alt`, `us-equity`,
   `energy`, `metals`, `fx-macro`) with a default mapping shipped in `config/default.yaml`.
4. **Duplicate-underlying block:** candidates whose cluster *and* underlying tag match an open
   position on the same side are rejected outright (`CL` + `BRENTOIL` ⇒ same `energy:oil` underlying).

Violations reject the candidate with a structured reason (`exposure_gross_cap`,
`exposure_net_cap`, `exposure_cluster_cap`, `exposure_duplicate_underlying`) that is journaled
to `llm_entry_gate_log` via the existing `reason_code` column — *without* an LLM call.

### WS4 — Gate-Call Economy (implements the LLM-infrastructure doctrine at the gate seam)

Deterministic pre-screens ahead of `LlmEntryGate.evaluate`, each journaled with a reason code
and each individually toggleable in config:

1. **Per-symbol verdict cooldown:** a reject for symbol+side suppresses re-evaluation for
   `gateCooldownMinutes` (default 60) unless the candidate's edge improved by ≥ 25% or a new
   catalyst timestamp is present.
2. **Edge floor:** candidates below `autonomy.minEdge` never reach the LLM (currently the floor
   exists but candidates at/near it are still consulted).
3. **Same-side stacking check:** moved from LLM discretion (`same_symbol_stacking` reason code,
   `src/core/llm_entry_gate.ts`) to a deterministic PositionBook check beside `hasConflict`.
4. **Exposure guard (WS3)** runs before any LLM consult.

**Acceptance metric:** gate LLM call volume drops ≥ 80% at equal-or-better approve quality
(approves/day unchanged ±20%, no increase in `book_conflict` approvals).

### WS5 — Heartbeat Repair

`ThufirAgent.handleHeartbeat` (`src/core/agent.ts:715`) stops routing through the full
`ConversationHandler.chat` pipeline. It uses the trivial/info client with a minimal liveness
prompt, honoring `notifications.heartbeat.timeoutMs` (new default 30,000ms) with the existing
`degradedMode` semantics unchanged. One failure per hour is logged at `warn`; repeated failures
escalate once per 6h to the existing notification path instead of erroring every tick.

### WS6 — Data Lifecycle

A `memory/retention.ts` registry where each repo declares `{table, kindColumn?, retainDays, keepKinds?}`.
A daily scheduler job applies registered policies and runs `PRAGMA incremental_vacuum`.

Initial registrations:

| Table | Policy |
|---|---|
| `decision_artifacts` | kinds `position_heartbeat_journal`, `expression`, `hypothesis`, `signal_cluster`: 21 days; trade-linked kinds (`perp_trade_*`, `execution_learning_case`, `adaptive_*`): retain |
| `opportunity_rank_logs` | 30 days |
| `llm_entry_gate_log` | rejects 90 days; approve/resize retained |
| `chat_messages` | unchanged (user data — out of scope) |

One-time migration prunes the existing 2.8M-row backlog in batched deletes.

### WS7 — Single Source of Current Truth (docs)

- New root `STATE.md`: current release, what is live in production (branch/SHA), active success
  criteria and their latest scorecard values, links to the active PRD/TDDs. Updated as part of
  every promotion to `main` (added to the PR checklist in `CLAUDE.md`).
- Root `PROGRESS.md` and `HANDOFF.md` gain a deprecation banner pointing to `STATE.md` and move
  to `docs/archive/` together with pre-v1.9 design docs (Augur-era content).

# TDD

## Current Proven Repo State

The seams this release needs already exist; v2.5 strengthens them rather than adding parallel structures:

- `src/core/position_heartbeat.ts` — already distinguishes TTL review, invalidation breach,
  exit-contract evaluation, emergency handling, and legacy triggers in separate branches; the
  reduce-only call sites only need to *pass* the branch identity they already know.
- `src/execution/modes/paper.ts` / `src/memory/paper_perps.ts` — fills already persist a
  `metadata` JSON column; no schema change needed for WS1 on the paper path.
- `src/core/llm_entry_gate.ts` — already has one deterministic fast-path (`hasConflict`, line ~594)
  and a closed `reasonCode` enum including `book_conflict` and `same_symbol_stacking`; WS3/WS4
  extend this pattern.
- `src/core/config.ts` — `wallet.exposure` and `wallet.perps.maxTotalNotionalUsd` /
  `sameSideExposureCaps` already exist as Zod schema; WS3 adds the missing keys and, critically,
  the missing *enforcement call site*.
- `src/core/position_book.ts` — `BookEntry` already carries `currentMarkPrice` and
  `unrealizedPnlUsd`, sufficient to compute gross/net/cluster exposure without new market calls.
- `src/core/scheduler_control_plane.ts` + `src/gateway/index.ts` (`scheduler.registerJob`, ~line 272)
  — job registration pattern for WS2/WS6 nightly jobs.
- `src/memory/llm_entry_gate_log.ts` — `reason_code` column exists; deterministic rejections
  reuse it with `used_fallback = 0` and a new `llm_consulted INTEGER DEFAULT 1` column to make
  the WS4 acceptance metric directly queryable.

**Tests**

  emergency, legacy trigger) produces a fill whose metadata reason matches the branch.

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Exposure guard bricks all trading (caps too tight for a $283 account) | `enabled` kill switch; caps in config not code; Task 2 acceptance includes a "new long is allowed" assertion against the live-book fixture |
| Cooldown suppresses a genuinely new setup | Edge-improvement and fresh-catalyst bypasses; cooldown state is journaled and queryable |
| Attribution threading misses a close path and blocks a close | Fail-open by design: unattributed close still executes, logs an error, writes `reason:'unattributed'`; acceptance query monitors for it |
| Backlog prune locks the DB under live writes | Batched deletes with sleep intervals; run as a manual deploy step; WAL mode already active |
| Scorecard reads contaminated history | Hard `cleanDataCutoff` filter in every query; cutoff date confirmed against the deploy log before merge |
| Cluster map goes stale as new markets list | Unmapped symbols are fail-contained (singleton clusters), and the retention job logs unmapped symbols seen in the book weekly |
