# TDD: Adaptive Learning Runtime Wiring — v2.3

## Scope

Wire the existing adaptive infrastructure into a production-real loop without changing the core decision architecture.

This release must fix three concrete runtime gaps:
- missing `signal_scores` on live perp prediction writers
- missing write path into `trade_policy_adjustments`
- missing production-grade observability proving adjustments and weight learning are actually consumed

## Current Proven Runtime State

Live production already proves these seams exist:
- `src/core/autonomous.ts` writes perp predictions and open dossiers
- `src/core/tool-executor.ts` handles the close path
- `src/core/tool-executor.ts` already writes:
  - `trade_dossiers`
  - `review_payload`
  - `trade_counterfactuals`
  - `execution_quality` learning cases
  - paired `thesis_quality` learning cases
  - `trade_similarity_features`
- `src/core/autonomous.ts` already reads active policy adjustments through:
  - `loadRuntimePolicyAdjustments(...)`
  - `applyAdaptiveDecisionEnforcement(...)`

Therefore this release should extend existing seams, not invent new ones.

## Design

### 1. Signal-score persistence for perp predictions

#### Problem

`src/memory/learning.ts` only updates weights and writes audits when `input.signalScores` is present.
Current perp prediction writers in `src/core/autonomous.ts` do not pass `signalScores`.

#### Required change

Add a helper in the perp decision path:
- `buildPerpSignalScores(...)`

Responsibilities:
- return `{ technical, news, onChain }`
- normalize values into the same bounded domain expected by `updateSignalWeights(...)`
- be deterministic
- return `null` only when the trade should not participate in signal-weight learning

Initial mapping requirements:
- `signalClass` and `entryTrigger` must influence the technical/news balance
- `noveltyScore` and `marketConfirmationScore` should contribute when available
- originator-only trades must still emit a stable fallback vector instead of omitting scores entirely

#### Writers to update

At minimum:
- `src/core/autonomous.ts` originator open path
- `src/core/autonomous.ts` quant scan open path

Each updated `createPrediction(...)` call must pass:
- `signalScores`
- `signalWeightsSnapshot` when available

### 2. Policy adjustment materialization on full close

#### Problem

`deriveTradePolicyAdjustments(...)` and `createTradePolicyAdjustment(...)` exist, but no runtime path calls them.

#### Required change

Add a new close-time materialization helper, e.g.:
- `src/core/trade_policy_materialization.ts`

Core function:
- `materializeTradePolicyAdjustmentsFromClose(...)`

Inputs:
- closed dossier
- execution learning case
- paired thesis case
- derived similarity features
- recent comparable closed evidence set

Outputs:
- inserted or refreshed `trade_policy_adjustments`
- deactivated stale adjustments for the same scope/key when evidence no longer supports them

#### Placement

Call this helper in `src/core/tool-executor.ts` only after all of these succeed for a fully closed position:
- `upsertTradeDossier(...)`
- `buildPerpExecutionLearningCase(...)`
- `createLearningCase(...)`
- `createTradeCounterfactual(...)`
- `upsertTradeSimilarityFeatures(...)`

This guarantees the materializer runs on the same evidence the retrieval path already uses.

### 3. Evidence aggregation rules

The materializer should not operate on a single close.

Add an aggregation helper that builds `TradePolicyAdjustmentEvidence[]` from recent closed dossiers and similarity features for the same scope.

Initial scope dimensions:
- `signalClass`
- `triggerReason`
- `symbolClass`
- `marketRegime`

Optional dimensions when present and adequately sampled:
- `direction`
- `session`
- `strategySource`

Evidence extraction should read from:
- `trade_similarity_features.failure_mode`
- `trade_similarity_features.success_driver`
- `trade_similarity_features.gate_verdict`
- dossier close payload for realized/net PnL
- dossier review payload for entry/sizing/exit labels
- execution/thesis learning cases for outcome and quality values

### 4. Adjustment persistence semantics

`trade_policy_adjustments` currently supports create/list/deactivate, but not idempotent refresh semantics.

Required implementation behavior:
- one active adjustment per effective `(policy_domain, policy_key, scope)` at a time
- creating a stronger refreshed adjustment should deactivate the older active row
- evidence windows and confidence must be persisted
- adjustments may optionally expire automatically

Recommended implementation:
- add `upsertTradePolicyAdjustment(...)` or `replaceActiveTradePolicyAdjustment(...)`
- reuse current scalar/payload schema

### 5. Runtime observability

#### Signal-learning observability

The existing `recordLearningSignalAudit(...)` path should reactivate automatically once `signalScores` are present.

Add targeted tests to prove:
- prediction writer persists `signal_scores`
- `recordOutcome(...)` produces `weight_updates`
- `recordOutcome(...)` produces `learning_signal_audits`

#### Policy-adjustment observability

Decision-time traces must show adjustment use.

No new trace schema is required if current fields are populated:
- `activePolicies`
- `activeAdjustmentIds`
- `sizeHaircuts`
- `leverageCaps`
- `confirmationRequirements`
- `triggeredCooldowns`
- `adaptationChangedOutcome`

### 6. Comparable forecast branch

Do not re-enable synthetic perp comparables in this release.

Keep:
- `isSyntheticPerpComparableInput(...)`
- `cleanupSyntheticPerpComparableRows(...)`

Reason:
- production traffic is currently perp-only
- fake `market_probability = 0.5` comparables would contaminate the calibration corpus again

## Runtime Hook Plan

### A. Open path

In `src/core/autonomous.ts`:
- build `signalScores`
- pass `signalScores` into perp `createPrediction(...)`

### B. Close path

In `src/core/tool-executor.ts`, on `closedPositionCompletely`:
- build dossier review
- upsert dossier
- build execution learning case
- persist paired learning cases
- persist counterfactuals
- upsert similarity features
- materialize policy adjustments

### C. Future open path consumption

No new read-path seam is required.

Existing read path:
- `loadRuntimePolicyAdjustments(...)`
- `selectRuntimeTradePolicyAdjustments(...)`
- `applyAdaptiveDecisionEnforcement(...)`

This release succeeds when that existing path starts receiving non-empty adjustments.

## Test Matrix

### Unit

1. `buildPerpSignalScores(...)`
- originator case yields stable non-null vector
- quant/news-heavy case tilts toward `news`
- technical-heavy case tilts toward `technical`
- mixed/unknown case still returns bounded normalized values

2. `deriveTradePolicyAdjustments(...)`
- weak win-rate evidence creates size + confidence penalties
- repeated helpful gate interventions create confirmation policy
- repeated failure mode creates cooldown policy
- below-threshold evidence creates no actionable output

3. adjustment replacement semantics
- replacing same `(policyDomain, policyKey, scope)` deactivates prior active row
- non-overlapping scopes coexist

### Integration

1. prediction resolution with `signal_scores`
- create prediction with scores
- resolve outcome
- assert:
  - `learning_events` row exists
  - `weight_updates` row exists
  - `learning_signal_audits` row exists

2. full close lifecycle
- execute open
- execute full close
- assert:
  - dossier closed
  - review persisted
  - counterfactual rows persisted
  - execution + thesis learning cases persisted
  - similarity features persisted
  - policy adjustments persisted when evidence threshold is met

3. future decision consumption
- seed active policy adjustment
- run adaptive decision enforcement
- assert:
  - `activeAdjustmentIds` non-empty
  - size/leverage/confirmation/reject behavior changes as expected

### Release-contract tests

Add an end-to-end contract test that simulates:
- open trade with signal scores
- close trade with sufficient evidence
- materialized adjustment
- subsequent decision affected by the adjustment

The test must assert both:
- persistence surfaces
- runtime behavior change

## Migration / Safety Rules

- Do not mutate historical perp rows back into comparable calibration examples.
- Do not allow a single closed trade to create a broad high-authority adjustment.
- Default to no adjustment when evidence shape is incomplete.
- Close-path materialization must be best-effort but must emit an alert/log on failure.
- Decision-time enforcement must remain deterministic and bounded.

## Done Definition

Implementation is done only when:
- new perp predictions persist `signal_scores`
- post-close resolution creates `weight_updates` and `learning_signal_audits`
- fully closed trades can materialize `trade_policy_adjustments`
- later decisions read those adjustments and expose them in traces
- the production validation plan for this release passes on the deployed SHA
